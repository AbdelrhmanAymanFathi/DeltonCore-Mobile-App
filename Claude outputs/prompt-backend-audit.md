> برومبت جاهز للنسخ — الصقه للـ builder الشغّال على كود نظام Delton Core People.

---

أنت شغّال على كود نظام **Delton Core People** (Django). المطلوب منك **تقرير استطلاعي فقط**.

**ممنوع تمامًا:** تعديل أي ملف، إنشاء migration، تشغيل أي أمر يغيّر قاعدة البيانات، أو إضافة كود جديد. مهمتك قراءة وتوثيق فقط.

**السياق:** فريق تانٍ هيبني تطبيق موبايل (React Native) يستهلك نفس هذا الباك إند عبر مسارات جديدة تحت `/api/mobile/`. التطبيق هيعمل: تسجيل حضور بـ GPS، وصندوق طلبات موحّد يعرض الإجازات والسلف والأذونات والجزاءات المنتظرة قرار المستخدم مع موافقة/رفض، وإخطارات Push. محتاجين نعرف بالظبط إيه الموجود في الكود قبل ما نبني أي حاجة.

**المخرَج:** ملف markdown واحد اسمه `BACKEND_AUDIT.md` في جذر المشروع، يتبع الأقسام التالية بالترتيب.

**قاعدة حاكمة:** لا تخمّن ولا تلخّص. افتح الملف واقرأه. لو الحاجة موجودة، **انسخ تعريفها من الكود حرفيًا**. لو مش موجودة، اكتب "غير موجود" صراحةً. ممنوع عبارات زي "على الأرجح" أو "يبدو أن".

## 1. خريطة المشروع

- إصدارات: Python، Django، djangorestframework، ونوع قاعدة البيانات
- قائمة `INSTALLED_APPS` كاملة
- كل app في المشروع ومسار مجلده
- محتوى `urls.py` الجذر كما هو
- هل `rest_framework_simplejwt` مثبّت؟ انسخ `REST_FRAMEWORK` و`SIMPLE_JWT` من settings إن وُجدا
- `TIME_ZONE`، `USE_TZ`، إعدادات CORS، `ALLOWED_HOSTS`
- أي `SECURE_*` settings (هل في إعداد HTTPS حاليًا؟)

## 2. نماذج الطلبات الأربعة

اعمل قسمًا فرعيًا مستقلًا لكل نوع: **الإجازة**، **السلفة**، **الإذن**، **الجزاء**. في كل قسم:

- هل النموذج موجود؟ اسمه بالظبط ومسار ملفه
- **انسخ تعريف الـ model كاملًا من `models.py` حرفيًا** — كل الحقول، الـ choices، الـ Meta، والـ methods
- حقل الحالة: اسمه وكل قيمه الممكنة
- كيف يرتبط بالموظف وبالمعتمِد
- لو النوع غير موجود: قل ذلك صراحة، ووضّح إن كان في الكود أي شيء قريب منه يمكن البناء عليه

## 3. سير الاعتماد (Approval workflow)

- كيف تُنفَّذ الموافقات متعددة المستويات؟ انسخ الـ models والدوال المسؤولة كاملة
- كيف يُحدَّد "المعتمِد الحالي" لأي طلب؟ انسخ الكود
- ماذا يحدث عند الموافقة وعند الرفض؟ (تغيير الحالة، الانتقال لمستوى تالٍ، أي side effects)
- هل يوجد سجل تدقيق يحفظ مَن اعتمد ومتى؟ انسخ نموذجه
- هل سير الاعتماد موحّد بين الأنواع الأربعة أم لكل نوع منطقه الخاص؟

## 4. الصلاحيات (RBAC)

- كيف تُعرَّف الأدوار والصلاحيات؟ انسخ النماذج
- **قائمة كاملة** بكل permission codenames المتعلقة بـ: الحضور، الجزاءات، الإجازات، السلف، الأذونات
- كيف يُقيَّد `Site Supervisor` بموقعه؟ انسخ الكود الذي يطبّق هذا القيد
- كيف يُتحقَّق من الصلاحية داخل الـ views؟ (decorator / mixin / permission class) — انسخ مثالًا كاملًا

## 5. الحضور

- انسخ نموذج `Attendance` كاملًا
- انسخ view الخاص بـ `attendance/punch/` كاملًا
- شكل الـ request والـ response بالظبط: أسماء الحقول وأنواعها
- منطق التحقق من GPS: انسخه كما هو، وحدّد نطاق المسافة المسموح به وأين يُعرَّف بالظبط
- انسخ view الخاص بـ `attendance/site-employees/`

## 6. الموظف والموقع

- انسخ نموذجي `Employee` و`Site` كاملين
- كيف يرتبط `User` بـ `Employee`؟ انسخ العلاقة

## 7. المصادقة الحالية

- كيف يسجّل المستخدم دخوله حاليًا؟ (session / token / غيره) — انسخ الـ view
- هل يوجد أي API authentication معرَّف حاليًا؟
- كيف يُعطَّل حساب مستخدم، وما أثر ذلك على جلساته القائمة؟

## 8. الإخطارات والمهام الخلفية

- هل يوجد أي نظام إشعارات (داخل النظام أو بريد)؟ انسخ ما يوجد
- هل يوجد Celery أو أي task queue؟ ما إعداداته؟

## 9. ملاحظات المطوّر

أي شيء في الكود يجب أن يعرفه مَن سيبني API موبايل فوقه: قيود، ديون تقنية، أماكن منطق الأعمال مكرَّر فيها، أي جزء هشّ يسهل كسره.
